# spotify-to-ytmusic

Spotify のプレイリストを YouTube Music へ移行する、個人用の CLI + Web UI です。

曲を 1 つずつ手で探す代わりに、プレイリストを指定すれば毎日少しずつ自動で移行します。

- **公式の YouTube Data API v3 だけを使います。** 非公式 API やスクレイピングを使わないので、利用規約違反やアカウント停止のリスクがありません。
- 進捗は SQLite に残ります。中断しても、翌日そのまま続きから再開します。
- **毎日の自動実行**（launchd）と、**スマホから見られる Web UI** が付いています。

---

## 先に知っておくこと

このツールを使うか決める前に、以下の 3 つを理解してください。**あとから回避できません。**

### 1 日 66 曲しか移行できません

YouTube Data API の無料枠は 1 日 10,000 units です。1 曲あたり以下を消費します。

| 呼び出し | コスト | 用途 |
|---|---|---|
| `search.list` | 100 | 曲を検索する |
| `videos.list` | 1 | 候補の再生時間を取得する |
| `playlistItems.insert` | 50 | プレイリストに追加する |
| 合計 | **151** | |

`10,000 ÷ 151 = 66 曲/日` です。500 曲なら 8 日、2,000 曲なら 1 か月かかります。

増枠には Google の監査申請が必要で、個人用途ではまず通りません。**急ぐなら TuneMyMusic などの既製サービスを使ってください。**

### 認可が 7 日で切れます

Google の OAuth アプリを「本番環境」に公開するには、**ホームページ URL とプライバシー ポリシー URL** が必要です。個人用ツールでは用意できないため、公開ステータスは「テスト」のままになります。

テストモードのリフレッシュトークンは **7 日で失効** します。移行が 7 日を超える場合、`invalid_grant` で止まるので、そのつど手で再認可してください（`make reauth-yt` → `make run`）。ブラウザでの操作が必要なので、リモートからは復旧できません。

### 他人のプレイリストは移行できません

Spotify の開発モードのアプリは、**自分が作成したプレイリストの中身しか読めません**。フォローしているだけのプレイリストは 403 になります。

移行できるのは「自分が作ったプレイリスト」と「Liked Songs」だけです。

## セットアップ

10 分ほどかかります。ブラウザでの操作が必要な部分は自動化できません。

### 1. Spotify のアプリを作る

1. https://developer.spotify.com/dashboard を開く

   > ⚠️ **最大の落とし穴。** ここでログインする Spotify アカウントは、**普段音楽を聴いているアカウントと同じ**にしてください。
   >
   > Google ログインなどで別のアカウントが作られていると、そのアカウントがアプリのオーナーになります。開発モードのアプリはオーナーまたは登録済みテスターしか使えないため、**すべての API 呼び出しが 403 になります。**
   >
   > 自分のアカウントのメールアドレスは https://www.spotify.com/account/profile/ で確認できます。

2. **Create app**
3. 入力する
   - App name: 任意
   - **Redirect URI**: `http://127.0.0.1:8888/callback` → **Add**

     > ⚠️ `localhost` は Spotify に拒否されます。必ず `127.0.0.1` を使ってください。

   - Which API/SDKs are you planning to use?: **Web API**

     > チェックボックスがグレーアウトして選べないことがありますが、既定で有効なので問題ありません。そのまま進めてください。

4. **Settings** から **Client ID** と **Client secret** を控える

**別アカウントで作ってしまった場合**は、アプリの **Settings → User Management** に、音楽を聴いているほうのアカウントのメールアドレスを追加します。**反映まで最大 15 分かかります。** 追加直後は 403 のままなので、待ってから再試行してください。作り直せるなら、正しいアカウントで作り直すほうが確実です。

### 2. Google Cloud の OAuth クライアントを作る

1. https://console.cloud.google.com/ で **新しいプロジェクト** を作る
2. 「APIとサービス」→「ライブラリ」→ **YouTube Data API v3** を **有効にする**
3. 「APIとサービス」→「OAuth 同意画面」（現在の名称は **Google Auth Platform**）→ **開始**
   - アプリ名 / ユーザーサポートメール / デベロッパーの連絡先を入力
   - 対象（Audience）: **外部**
4. 「**対象**」タブ →「**テストユーザー**」に、**YouTube Music を使っている Google アカウント**を追加する

   > ⚠️ ここを飛ばすと、認可画面で `エラー 403: access_denied`（「デベロッパーに承認されたテスターのみがアクセスできます」）になります。

5. 「**クライアント**」タブ →「**クライアントを作成**」
   - アプリケーションの種類: **デスクトップ アプリ**
6. **クライアント ID** と **クライアント シークレット** を控える

JSON のダウンロードは不要です。値は `.env` に書きます。

### 3. `.env` を作る

```bash
cp .env.example .env
```

```
SPOTIPY_CLIENT_ID=（Spotify の Client ID）
SPOTIPY_CLIENT_SECRET=（Spotify の Client secret）
SPOTIPY_REDIRECT_URI=http://127.0.0.1:8888/callback

GOOGLE_CLIENT_ID=（Google の クライアント ID）
GOOGLE_CLIENT_SECRET=（Google の クライアント シークレット）
```

### 4. 依存パッケージ

```bash
make setup
```

## 使い方

```bash
make list                 # 自分のプレイリスト一覧
make add PL="7 15"        # 番号・名前・URL のいずれでも指定できる
make liked                # Liked Songs を登録
make all                  # 自分の全プレイリストを登録
make run                  # クォータの許す範囲で移行する
make status               # 進捗
make sync                 # Spotify 側の変更を取り込む
```

初回の `make list` と `make run` で、それぞれ Spotify と Google の認可のためにブラウザが開きます。

Google では「このアプリは Google で確認されていません」と警告が出ますが、自分で作ったアプリなので **「詳細」→「（アプリ名）に移動」** で続行してください。

認可するアカウントを間違えないように注意してください。プレイリストは**認可したアカウント**に作られます。

### 未マッチ曲

一定のスコアに満たない場合、**誤った曲を登録せず** `unmatched` として記録します。

```bash
make export               # unmatched.csv に書き出す
make inspect T="曲名"      # 検索候補とスコアの内訳を見る（101 units 消費）
make retry                # 未マッチ・失敗した曲を再検索対象に戻す
```

Web UI からは、未マッチ曲に YouTube の URL を貼って手動で割り当てられます。

## Web UI

```bash
make web       # 手動で起動
make urls      # アクセス用 URL を表示
make install-web   # Mac 起動時に自動で立ち上がるよう常駐させる
```

- プレイリストごとに「これから移行する曲 / 未マッチの曲 / 失敗した曲 / 移行済みの曲」を折りたたみで表示
- 今日のクォータで処理される曲に「今日」バッジ
- Spotify 側に変更があれば「Spotify側に変更あり」バッジ → ボタンで差分取り込み
- 未マッチ曲に YouTube 動画を手動で割り当て

### トークンによる権限分離

`.env` に 3 種類のトークンを設定できます。用途に応じて使い分けてください。

| | `WEB_VIEW_TOKEN` | `WEB_QUEUE_TOKEN` | `WEB_TOKEN` |
|---|---|---|---|
| 進捗の閲覧 | ✓ | ✓ | ✓ |
| プレイリストの登録・同期・実行 | | ✓ | ✓ |
| キュー解除・一時停止・再試行・手動修正 | | | ✓ |

```bash
make token     # ランダムなトークンを生成する
```

権限は**サーバー側で判定**しています。ボタンを隠しているだけではないので、URL を直接叩かれても操作されません。

> ⚠️ `WEB_HOST` を `127.0.0.1` 以外にする場合、`WEB_TOKEN` は必須です。**未設定だとサーバーは起動を拒否します。** このサーバーは Spotify と YouTube の有効な認証情報を保持しているため、無防備に公開するとアカウントを操作されます。

### スマホから使う

`.env`:

```
WEB_HOST=0.0.0.0
WEB_TOKEN=（PC 用）
WEB_QUEUE_TOKEN=（スマホ用。登録と実行ができる）
WEB_VIEW_TOKEN=（閲覧専用）
```

**同じ Wi-Fi 内なら**、`make urls` が表示する LAN アドレスをそのまま開けます。

**外出先からも使うなら [Tailscale](https://tailscale.com/) を推奨します。** Mac とスマホを同じプライベートネットワークに入れる仕組みで、インターネットには何も公開しません。無料で、コードの変更も不要です。

1. Mac に入れてサインイン（`brew install --cask tailscale`、または Mac App Store 版）
2. スマホにも入れて**同じアカウント**でサインイン
3. `make urls` が表示する `*.ts.net` の URL をスマホで開く

URL は固定なので、ホーム画面に追加できます。

> `brew install --cask tailscale` は `sudo` のパスワードを要求します。**Terminal.app などの実際の端末で実行してください。** エディタや AI エージェント経由では入力できず失敗します。Mac App Store 版なら sudo 不要です。

**Mac がスリープ・電源オフのときは応答しません。** これは Tailscale の制約ではなく、サーバーが Mac 上で動いているためです。

## 毎日の自動実行

```bash
make install-agent        # 毎日 17:30 に実行するよう登録
make agent-status         # 登録状況
make logs                 # ログを追尾
make uninstall-agent      # 解除

HOUR=9 MINUTE=0 make install-agent   # 時刻を変える
```

毎日次を行います。

1. `migrate.py sync` — Spotify 側で曲が増減していれば取り込む
2. `migrate.py run` — クォータを使い切るまで移行する

**cron ではなく launchd を使っています。** cron はスリープ中に予定時刻を過ぎるとその回を飛ばしますが、launchd は Mac が起きたときに実行し直します。ノート PC で使う場合はこの差が効きます。

クォータのリセットは太平洋時間の 0 時（日本時間 16:00、冬時間は 17:00）なので、既定の 17:30 はその後になります。**別のタイムゾーンで使う場合は実行時刻を調整してください。**

### 蓋を閉じたままでも実行したい場合

launchd はスリープ中には動きません。Mac を時刻指定で起こしてください。

```bash
sudo pmset repeat wakeorpoweron MTWRFSU 17:25:00   # 解除: sudo pmset repeat cancel
```

電源に接続しておくことを推奨します。

## 仕組み

### 曲のマッチング

Spotify の曲名で YouTube を検索し、候補を採点します（`matching.py`）。

- **公式音源チャンネル**（`アーティスト名 - Topic`）なら大きく加点
- 曲名の類似度、および**曲名がタイトルに含まれるか**
- **再生時間の一致**（±3 秒以内で加点、15 秒以上ずれていれば減点）
- 「cover」「歌ってみた」「remix」などが元の曲名に無いのに含まれていれば減点

**Spotify は日本人アーティスト名をローマ字で返します**（星野源 → `Gen Hoshino`）。YouTube 側は日本語表記なので、アーティスト名の文字列一致はしばしば失敗します。実測で未マッチの 6 割がこれでした。そのため、閾値に届かなくても次の場合は採用します。

- 再生時間が ±3 秒以内で、かつ曲名が類似または包含されている
- 公式音源チャンネルかつアーティストが一致し、再生時間が ±7 秒以内

閾値は `matching.py` の `ACCEPT_THRESHOLD` で調整できます。`make test` で回帰を確認してください。

### クォータの節約

`search.list` は 100 units と高価ですが、**`videos.list` は 50 件まで 1 unit** です。この非対称性を利用して、候補の再生時間を 1 unit で取得し、精度を上げています。

### Spotify 側の変更の検出

Spotify はプレイリストに `snapshot_id` を付けており、内容が変わると値が変わります。これを保存しておくことで、「同期が必要か」を 1 回の API 呼び出しで判定できます。

曲は**位置ではなく Spotify の track ID** で管理しています。曲を途中に挿入したり並べ替えたりしても、既存の曲が新規追加として重複することはありません。Spotify から削除された曲は `removed` として記録し、YouTube 側からは消しません。

### Spotify Web API のフィールド名変更への対応

Spotify はレスポンスの構造を変更しています（2026 年時点）。

| 旧 | 新 |
|---|---|
| プレイリストの `tracks` | `items` |
| エントリの `track` | `item` |
| `/playlists/{id}/tracks` | `/playlists/{id}/items` |

`spotify_client.py` は**両方のキーを見る**ようにしてあります。古いドキュメントや記事を参考にすると曲数が 0 になったり曲が取得できなくなるので注意してください。

## トラブルシューティング

### `403 ... the user may not be registered`（Spotify）

アプリのオーナーでも登録済みテスターでもないアカウントで認可しています。

1. https://www.spotify.com/account/profile/ で、**音楽を聴いているアカウントのメールアドレス**を確認する
2. Spotify Dashboard の対象アプリで **Settings → User Management** にそのアドレスを追加する（名前は照合に使われないので任意）
3. **最大 15 分待つ**
4. `rm .spotify_token.json` してから再実行し、**認可画面で正しいアカウントが選ばれているか確認する**

Dashboard を開いたときに「Developer Terms への同意画面」が出る場合、**そのアカウントは開発者登録をしていない** ＝ アプリを作ったアカウントではありません。

### `エラー 403: access_denied`（Google）

OAuth 同意画面の「対象」タブで、**テストユーザーに自分の Google アカウントを追加**してください。

「アプリを公開」ボタンが押せないのは正常です（ホームページ URL とプライバシー ポリシー URL が必要）。テストのままで問題ありません。

### `invalid_grant: Token has been expired or revoked`

テストモードの 7 日制限です。

```bash
make reauth-yt && make run
```

### 曲数が 0 と表示される / 曲が 1 つも取得できない

Spotify のフィールド名変更に対応していないコードです。`spotify_client.py` の `_total()` と `tracks()` が `items` / `item` を見ているか確認してください。

### 一覧に出ないプレイリストがある

自分が作成していないプレイリスト（フォロー中のもの）は、開発モードでは中身を読めないため非表示にしています。

### 未マッチが多い

```bash
make inspect T="曲名"   # スコアの内訳を確認（101 units 消費）
```

`T=Topic チャンネル / A=アーティスト一致 / C=タイトル包含 / !=減点語` のフラグと、類似度・再生時間差が表示されます。`matching.py` の `ACCEPT_THRESHOLD` を下げるか、採用ルールを追加してください。

調整後に再検索させるには `make retry` を実行します（1 曲あたり 151 units を再消費します）。

### Web UI が「Spotify のレート制限中です」と出る

Spotify Web API の 429 です。表示された時間だけ待てば自動的に復帰します。**移行処理そのものは YouTube 側の API なので影響を受けません**（自動実行は通常どおり進みます）。

制限中はサーバー側で Spotify への問い合わせを止めます。待っている間に「再取得」を連打しても、制限は延びません。

レート制限に達しやすい操作は次のとおりです。

- 「同期チェック」の連打（登録済みプレイリストの全曲を取得するため）
- ブラウザの再読み込みの繰り返し

**なぜ起きるか。** spotipy の既定では `429` がリトライ対象に含まれています（`default_retry_codes = (429, 500, 502, 503, 504)`、`max_retries = 3`）。429 を受けると `Retry-After` の秒数だけスリープしてから再送し、それも 429 になります。

つまり **1 回の呼び出しが 4 リクエストに膨らみ、リトライ自体が同じ枠を消費する**ため、制限の窓がいつまでも空きません。UI は最大で数時間「読み込み中」のまま固まります。開発モードのアプリは枠が小さいので、なおさら起きやすくなります。

このツールでは次の対策を入れています。

- `retries=0` にして即座に失敗させ、待ち時間を画面に表示する
- 制限中はサーバー側で Spotify への問い合わせ自体を止める
- 自前で呼び出しレートを制限する（30 秒あたり 20 回）
- 登録済みプレイリストの進捗は SQLite から返す。**Spotify が落ちていても画面は表示される**

### Web UI に繋がらない

サーバーが動いていない可能性が高いです。

```bash
pgrep -fl web.py           # プロセス確認
make install-web           # 常駐させる（Mac 起動時に自動で立ち上がる）
tail -f web-server.log     # ログ
```

## ファイル構成

```
migrate.py          CLI エントリポイント
web.py              FastAPI の Web サーバー（トークンによる権限分離）
runner.py           移行ループ本体。多重起動をファイルロックで排他
sync.py             Spotify との差分同期（snapshot_id で判定）
matching.py         曲のマッチングと採点
spotify_client.py   Spotify Web API
youtube_client.py   YouTube Data API（クォータコストを明示）
db.py               SQLite のスキーマとマイグレーション
static/index.html   Web UI（依存ライブラリなし）
scripts/            launchd への登録、URL 表示、日次実行
test_matching.py    マッチングの回帰テスト
```
